# Caelestia Switch — Session Handover

*As of 2026-10-03 (after the mask-path live tests, the snapshot-side fix and the `repair` implementation). Written so a fresh conversation can continue without re-deriving anything. Read this first, then the design docs (Section 10).*

## 1. The project in one paragraph

Build **`caelestia-switch`**, a standalone C++/Qt6 Widgets/KF6 app that switches between stock KDE Plasma (`plasmashell`) and **Caelestia KDE** (`ladybug-me/caelestia-kde`, a Quickshell-based shell) without uninstalling either. It must work with an **unmodified** upstream install. Masking plasmashell lives in the app, not in any installer. Later, the user builds his own modified fork of caelestia-kde, and the app's install/update/uninstall can pick upstream or the fork. The earlier "fork-first" plan was replaced on 2026-09-30.

## 5. Key decisions (full text in the architecture doc)

- **D1/D10:** masking is done by the app, not an installer; the app must work with unmodified upstream installs. **Pre-flight (amended 2026-10-02, user agreed):** live check before every mask; `RequiredBy` / `RequisiteOf` / `BoundBy` of `plasma-plasmashell.service` (or an unreadable answer) = refuse; `WantedBy` (always `plasma-core.target` in a live session) = allowed, with a warning naming the units. Implemented as `checkMaskPlasmashell` in `src/core/switch.cpp` (pre-flight, step 6, CLI note). The GUI (A4) runs the same check at load: strong = checkbox greyed out with the reason; weak = warning plus a "proceed?" question with "don't ask again".
- **Switch rules (D12):** to plasmashell: unmask it if masked, **always** stop and **disable** Caelestia (`disable --now`, not mask: the unit is a regular file in `~/.config/systemd/user`), restore the stock backup. To Caelestia: start it, restore the Caelestia backup; checkbox checked = stop and mask plasmashell, unchecked = leave plasmashell running headless (unmask and start it if needed). The checkbox only matters when switching to Caelestia.
- **Logout (D13):** always required, done last via `qdbus6 org.kde.Shutdown /Shutdown org.kde.Shutdown.logout`; show a "save your work" warning; never force-kill apps. Do the config swap after the outgoing shell has stopped.
- **Helper units (D14):** only `cliphist.service` is handled (the update checker is not a systemd unit; `ydotoold.service` is left alone). It is disabled on the way to stock only if nothing requires or is bound to it, and remembered in `~/.config/caelestia-switch/helpers`, so only units the app disabled are re-enabled on the way back. Failures are warnings.
- **Backups (D11, narrowed 2026-10-01):** two-sided, timestamped, snapshot of the mode being left taken automatically; stored in `~/.local/share/caelestia-switch/backups/<side>/<timestamp>/` with a manifest. Only what the installer writes persistently is backed up. Whole-file: `plasma-org.kde.plasma.desktop-appletsrc`, `plasmashellrc`, `kscreenlockerrc`, and `cli.json`/`keybinds.json`/`shell.json`/`monitors` from `~/.config/caelestia/`. Key-level with "absent in the snapshot means delete" on restore: `kwinrc` (`Desktops`, `Plugins` keys the installer sets, `org.kde.kdecoration2`), `kwinrulesrc` (the three `caelestia-*` rule groups and their `[General]` entries), `plasmarc`, `kdeglobals`, `plasmanotifyrc`, `powerdevilrc`, `kmixrc`, `ksplashrc`. **Not backed up:** `kglobalshortcutsrc`, electric-border keys, `stolen-*.json`, `[Tiling]` groups, Konsole. The installer's own konsave backup is not relied on.
- **Detection (D15, amended 2026-10-01):** *source* from an app-written marker (`~/.config/caelestia-switch/install.json`, only if its commit == `.current_commit`), else checkout discovery (`$CAELESTIA_DIR` or `~/caelestia-kde`, `HEAD` == `.current_commit`; source = `origin` URL), else "unknown". *Version* from the marker, else `~/.config/quickshell/caelestia/.current_version`, else the checkout's `.github/version.env`, else "unknown". No first-run question.
- **Status rules (D17):** unit state over the user D-Bus (`LoadUnit` + `GetAll`), process scan of `/proc`, provider rule, the Inconsistent list, exit codes (0 normally, 3 if systemd unreachable).
- **Toolkit (D16):** C++ with Qt6 Widgets and KF6; core library + CLI + thin GUI. Build on the ASUS (clone, pull, build `-j2`); the MSI build is a compile check. Never use `-march=native`.
- **D4 resolved / D18 (2026-10-01):** a plain `systemctl stop` of Caelestia leaves its stolen shortcuts and screen corner in place; a graceful `quickshell kill -i <id>` (with `WAYLAND_DISPLAY` set) makes Caelestia release them itself. The switch quits Caelestia gracefully, waits for the unit to go inactive, then reloads the KWin Overview effect (`qdbus6 org.kde.KWin /Effects org.kde.kwin.Effects.reconfigureEffect overview`), then disables the unit.
- **D19 (switch executor, 2026-10-02):** the switch runs in a transient user service `caelestia-switch-run` (own cgroup), started by `on`/`off`; steps 1-8 (pre-flight, snapshot of the side left, stop BOTH shells in both directions (Caelestia gracefully, plasmashell always, since it may rewrite its config on exit), helper units, restore, unit changes, verify, pending-logout + logout), each checked and recorded in the state file `~/.config/caelestia-switch/state` (key=value, `mode=` first); a failed step stops without logging out. After the login `finish` waits for the expected readings, closes out the state (`mode` stock/caelestia, `result=done`, `unseen=true`). A lock file allows one switch at a time. **User-approved warning text** for the GUI before confirming: "This will log you out. Save your work now. This window will close when the session ends and continue running in the background until it finish." After login the app should reopen and say the switch is finished.
- **D19 addendum (2026-10-03, implemented, unit-tested and live-tested):** the snapshot side comes from `Readings.provider` (none = no snapshot, warning), and when Caelestia already runs and only the mask differs (`SwitchPlan::unitsOnly`) the switch does only unit changes + verify + logout (no snapshot, no stop, no restore, no backup needed; `--backup` is refused). Reason: the old code would have filed the live Caelestia config as the newest stock backup and restored into the running Caelestia.
- **D20 (2026-10-03, implemented and unit-tested; interrupted-switch scenario live 2026-10-04):** `repair` rolls back to the side that was left (snapshot of step 2), prints the failure and its cause first, falls back to stock Plasma when nothing says which side was left, refuses the normal `pending-logout` wait, starts the shell being restored if the rollback itself fails, and keeps `snapshotRef` and the original `cause` so it can be repeated. New optional state keys: `leaving`, `plasmaWasMasked`, `failedStep`, `cause`, `rolledBack`; result `rolled-back`. Retrying a switch is possible after `repair` + `finish`; pre-flight refusals write no failed record. 2026-10-04 live findings (fixed, unit-tested, 29 tests): the rollback restores the snapshot whenever the failed switch may have rewritten config (`configMayBeTouched`) instead of trusting readings that look right; a timed-out `systemctl start` in the safety net is reported as "asked systemd to start", not "could not start"; the restore error text no longer repeats itself.
- **D8/update:** `update` is manual only. Upstream's update checker and `update.sh` hardcode `ladybug-me/caelestia-kde` and accept only branches `main`/`dev`.
